# Changelog

## Unreleased

- Added one descriptor-bound mount capability and assurance model across Goal, repository evidence, package creation, and Apply mutation/destruction. Linux providers cover fdinfo `mnt_id`, `statx`, and `name_to_handle_at`; Darwin uses `fstatfs`; successful comparable providers must reconcile, while `fstat().st_dev` remains diagnostic-only and low/unavailable assurance fails closed.
- Added a dependency-free human/JSON doctor with stable capability and remediation codes that deliberately omits raw mount identities, filesystem paths, trust material, and environment secrets.
- Split deterministic schema-v3 distribution into plugin-root and full-source ZIPs with shared producer/verifier policy, canonical byte output, strict portable denylist and ZIP-envelope enforcement, pre-parser ZIP64/member-count/archive/central-directory budgets, one immutable verification/extraction snapshot, mount-aware no-follow extraction/root revalidation, umask-independent canonical extraction with safe restrictive installed-copy directory-mode compatibility, hardlink/nested-mount, unexpected-empty-directory, unsafe-directory-mode, and unexpected-plugin-surface rejection, narrowly canonical schema-v2 source read compatibility, stable path-safe exporter CLI output, and explicit non-release provenance modes. Extraction cleanup that cannot prove safe removal now reports `package_extract_cleanup_state_unknown` and preserves a recovery artifact. Legacy `export-sanitized*` targets remain source aliases without regenerating the ambiguous historical filename.
- Split validation into static, unit, real-platform, behavior, package, schema, privacy, and strict-release gates. Portability CI now covers Ubuntu Python 3.12/3.13/3.14 and macOS Python 3.13/3.14; release provenance stays out of normal push/pull-request and `check-fast` paths.
- Made CodexQB explicit-invocation only with `policy.allow_implicit_invocation: false`, plus a canonical activation-metadata validator that rejects duplicate sections/keys, quoted or non-boolean policy values, merge/flow shapes, and silent auto-activation regressions.
- Added a pinned development/CI-only Draft 2020-12 parity gate for the public Apply schema. It meta-validates the schema, maps every runtime filename to its intended `$defs`, rejects permissive root-union false passes and undeclared writer fields, and keeps default/runtime validation dependency-free.
- Hardened sanitized packaging with explicit strict-release, worktree, and filesystem-source modes; exact Git/changelog/tag provenance checks with replacement objects and inherited `GIT_*` repository routing disabled; rejection of assume-unchanged, skip-worktree, and other non-normal index state; strict byte/mode binding of both packaged and sanitizer-excluded tracked files to the manifest's release commit; payload-derived release metadata; a final pre-publication Git snapshot; portable casefolded tracked-source and inode-based Git-metadata output collision guards; bounded captured-byte hashing/writes; and portable path ordering. Package manifest schema v2 binds each SHA-256 to its normalized `0644`/`0755` mode. Publication keeps the verified temporary inode open through replace, reopens and re-verifies the published inode, rolls a failed publication back to an identity-pinned same-directory backup, and preserves that backup if automatic recovery fails. The dependency-free verifier rejects ambiguous, unsafe-mode, standalone bytecode, or oversized inputs, uses linear ancestor checks, and validates extracted trees through no-follow descriptor traversal, identity-bound hashes, and a second inventory. Non-Git package validation now requires the manifest instead of silently regenerating one after deletion. Manifest hashes are consistency metadata, not a publisher signature or host attestation.
- Added a locked canonical SHA-256 chain to `Events.jsonl`. Every event binds the previous event hash and its own digest; validation and append now reject partial lines, malformed or duplicate-key JSON, reserved chain-field injection, sequence collisions, and broken/tampered links.
- Added one bounded secret-safety layer for persistent Goal/Apply JSON, JSONL, Markdown, patches, and console diagnostics. It rejects duplicate JSON keys; scans decoded structured name/value and pair contexts, renderer-visible Markdown/control forms, validation stdout/stderr before receipts, run names before directory creation, and repository bytes before base64 encoding and after decoding. Implementer/fixer returns now persist only through controller-owned `normalize-writer`, with report hashes and normalization events required for later state. Findings fail closed without echoing credential values; exact canonical placeholders remain valid.
- Bumped Apply runtime artifacts to `apply_run_schema_version: 3`. Schema-v1 and schema-v2 Apply runs predate the live evidence receipt contract and are archive-only; they cannot be validated, resumed, replaced, trusted-verified, finalized, or synthetically migrated into v3.
- Restricted destructive Apply `--replace` operations to registered direct children of `.codexqb/apply-runs/`, with complete-manifest digests, descriptor-anchored initialization, an out-of-repository HMAC trust key plus no-silent-rotation state record, signed run/root-inode-bound receipts published last, entry-root descriptors, late mount/identity rechecks, stale-receipt recovery gates, and directory-descriptor-bound atomic no-replace quarantine deletion. Synthetic or incomplete markers, repository roots, unmanaged paths, symlinks, mounts, namespace swaps, creation/registration races, missing initialized keys, and unsupported host primitives now fail closed. Schema-v3 runs require signed provenance for validation, resume, and replacement; schema-v1/v2 artifacts are rejected and cannot be used to downgrade current runs even after recomputing their schema-bound IDs.
- Replaced prefix-only validation-command allowlisting with a closed, root-aware seven-field envelope and tool-specific no-write profiles. Strict planning and Apply now reject mutation/output flags, unknown options or fields, sensitive or symlink-escaped cwd values, non-deny network, non-Tier-1 probes, executable spoofing, response files, and opaque wrappers; verified evidence is bound to the full canonical planned command core.
- Bound Goal and Apply policy envelopes with `goal_policy_digest` and `apply_policy_digest`, so validators recompute required inputs, write scopes, strict checkpoints, stop gates, workspace posture, readiness evidence, safety flags, budget caps, and agent policy instead of trusting artifact declarations.
- Made generated Goal validation checkpoints strict by default, including Step 2, Step 3 preflight/post-audit, and Step 4 gates.
- Replaced self-reported VERIFIED evidence with signed live receipts. `capture-evidence` binds the controller-generated patch and changed-file content hashes to the current repository state; `run-validation` executes every exact planned command and records command/cwd/exit/time/stdout/stderr plus explicit network, sandbox, approval, artifact, run, task, and change-set context; read-only reviewers return one structured JSON payload that the controller persists with `normalize-review` before recording completion; and `publish-review` signs the ordered `spec -> quality -> security if required -> final` chain. Only the latest published receipt for each validation ID and review phase is current, so a newer failure cannot be hidden by replaying an older pass. Missing, stale, modified, cross-run, reused, unnormalized, or wrong-order receipts fail closed, and a later diff change invalidates earlier verification.
- Distinguished controller evidence from host attestation. Controller-recorded AgentRuns use `identity_assurance: controller_asserted`, review normalization records `host_completion_proof: not_observed`, and a complete `subagent_serial` receipt chain remains explicitly unattested. Until the host supplies an agent identity/completion attestation contract, `VERIFIED` fails closed with `trusted_verified_requires_host_agent_attestation=<task-id>` and finalization remains blocked. Direct mode cannot independently issue the reviewer chain.
- Allowed Apply resume validation to accept exact untracked new files only when the task Implementation Contract declares the path as `state: proposed`; staged or contract-external files still block.
- Scoped Step 4 Goal snapshots to selected READY/READY_WITH_WARNINGS sub-plans so deferred sub-plan edits do not break the active implementation batch.
- Made Goal workspace inventory Git-aware through an executable-free plumbing allowlist plus descriptor-bound raw tracked/untracked content, kind, and mode evidence; explicit mutable/runtime paths are excluded before content capture. The non-Git fallback prunes common dependency, build, and cache directories through the shared bounded inventory.
- Replaced Apply's unbounded filesystem walk and whole-file workspace reads with a two-pass, streaming, descriptor/root-and-mount-bound inventory capped at 100,000 paths, 64 MiB per file, 512 MiB across both passes, and 60 seconds. Content/mode/symlink drift, root or parent replacement, same-device nested directory/file mounts, path floods, and limit overruns fail closed while explicit runtime exclusions are pruned before capture.
- Bumped the release surface to 0.3.0 with deterministic Goal previews and artifact-based Step 4 apply-run contracts.

- Added `references/apply-orchestrator.md` and dependency-free `scripts/apply_run.py` for `.codexqb/apply-runs/<apply-run-id>/` artifacts, apply modes, `no_action` mode, review-order validation, and default `commit_policy: none`.
